# Dst-Recorder

Приложение для записи экрана на macOS. Живёт в строке меню, пишет экран целиком или выбранную область вместе со звуком (микрофон + системный звук) в MP4 через нативный захват FFmpeg/AVFoundation.

> **Платформы.** Сейчас запись работает **только на macOS** (`ScreenRecorder.startRecording()` отклоняет другие платформы, список устройств строится через `avfoundation`). Сборка под Windows (`pnpm build:win`) технически собирается, но записывать не будет — поддержка Windows/Linux в планах.

## Возможности

- **Запись экрана или области**: выбор монитора или перетаскиваемая рамка для записи произвольной области.
- **Звук**: микрофон и системный звук одной дорожкой через агрегатное аудиоустройство (см. [Настройка звука](#настройка-звука-на-macos)).
- **Качество**: пресеты 720p / 1080p / 2K / 4K; пресеты выше физического разрешения монитора скрываются автоматически.
- **Пауза / продолжение**: паузы вырезаются из итогового файла автоматически (без перекодирования, доли секунды).
- **Плавающий таймер** с кнопками старт / пауза / стоп и быстрыми настройками.
- **Меню в строке меню (трей)**: старт/стоп, текущие экран и звук, длительность записи в заголовке трея, когда таймер скрыт.
- **Зелёная рамка** вокруг записываемого экрана (опционально).
- **Горячее подключение мониторов**: список экранов обновляется при подключении/отключении дисплея.
- Папка сохранения выбирается в настройках, по окончании записи файл открывается в Finder.

## Установка

Скачайте DMG из [Releases](../../releases) (есть сборки под Apple Silicon и Intel).

Приложение не подписано сертификатом Apple Developer, поэтому macOS может сообщить, что оно «повреждено». Быстрое решение:

```bash
xattr -cr /Applications/Dst-Recorder.app
```

Другие способы — в [INSTALLATION.md](INSTALLATION.md).

### Разрешения macOS

При первом запуске нужно выдать в **System Settings → Privacy & Security**:

- **Screen Recording** — для захвата видео;
- **Microphone** — для записи звука.

Без них запись не стартует: приложение покажет диалог с кнопками «Открыть настройки» и «Перезапустить приложение». После выдачи доступа к записи экрана приложение нужно перезапустить. Если в списке Screen Recording появится отдельно `ffmpeg`, отметьте и его.

## Использование

После запуска иконки в Dock нет — приложение работает из строки меню (иконка камеры).

| Пункт меню | Что делает |
|---|---|
| ▶️ Начать запись | Запись выбранного экрана с текущими настройками |
| ⚙️ Настройки | Окно настроек: экран, качество, звук, папка, рамка |
| ⏱️ Таймер | Плавающая панель управления записью |
| 📐 Область | Рамка для выбора области записи (перетаскивайте её мышью) |
| 📂 Открыть папку с записями | Открывает папку сохранения |

**Запись области.** Откройте «Область», расположите рамку, нажмите старт на таймере. Во время записи рамка становится «прозрачной» для кликов, таймер скрывается. После остановки настройки автоматически возвращаются к полному экрану.

**Пауза.** Кнопка паузы на таймере. Длительность пауз учитывается, и после остановки файл обрезается до реальной длины записи.

### Где что лежит

| Что | Путь |
|---|---|
| Записи (по умолчанию) | `~/Desktop/Dst-Recorder/REC_ДД-ММ-ГГГГ_ЧЧ_ММ_СС.mp4` |
| Настройки | `~/Library/Application Support/dst-recorder/dst-settings.json` |
| Логи | `~/Library/Logs/dst-recorder/main.log` |

Формат вывода: MP4, видео H.264 (`libx264`, `ultrafast`, CRF 23, `yuv420p`, 30 fps), звук AAC 192 kbps.

## Настройка звука на macOS

Приложение ожидает **одно** многоканальное устройство, в котором уже собраны микрофон и системный звук. При старте автоматически выбирается устройство, название которого начинается с `Recorder-Input` (иначе — первое из списка).

Понадобится виртуальный аудиодрайвер, например [BlackHole](https://github.com/ExistentialAudio/BlackHole) (`brew install blackhole-16ch`).

1. Откройте **Настройка Audio-MIDI** (`Cmd + Пробел` → «Audio MIDI Setup»).
2. Нажмите **`+`** в левом нижнем углу → **Создать агрегатное устройство**.
3. Отметьте «Исп.» у устройств **в таком порядке**: сначала ваш **микрофон**, затем **BlackHole 16ch**.
4. В **Источник тактов** выберите физическое устройство (микрофон) — виртуальный драйвер будет синхронизироваться по его часам.
5. Включите **Коррекция сноса** у BlackHole.
6. Переименуйте устройство в **`Recorder-Input`**.
7. Направьте системный звук в BlackHole: **Системные настройки → Звук → Выход**. Чтобы при этом слышать звук самому, создайте в Audio-MIDI **устройство с несколькими выходами** (наушники/динамики + BlackHole) и выберите его как выход.

Почему порядок важен: FFmpeg сводит каналы фильтром `pan=stereo|c0=2.5*c0|c1=1.0*c2` — канал 0 (микрофон, усиление ×2.5) идёт в левый, канал 2 (системный звук) — в правый. Если в агрегате другой порядок или стереомикрофон, громкость или раскладку придётся поправить в `src/ffmpeg.ts`.

## Разработка

### Требования

- macOS (для записи и проверки)
- Node.js 20+
- pnpm 8+

### Быстрый старт

```bash
git clone <repository-url>
cd dst-recorder
pnpm install   # postinstall сам докачает бинарники Electron и FFmpeg
pnpm dev       # Vite + Electron с hot reload
```

При установке pnpm может предупредить об игнорировании build scripts — это нормально, нужные бинарники ставит `scripts/postinstall.js`.

В dev-режиме разрешения Screen Recording/Microphone выдаются приложению, из которого запущен процесс (Terminal, iTerm, IDE).

### Команды

| Команда | Назначение |
|---|---|
| `pnpm dev` | Режим разработки |
| `pnpm compile` | Проверка типов + сборка Vite |
| `pnpm lint` / `pnpm lint-ci` | ESLint (CI-режим падает на предупреждениях) |
| `pnpm build:mac` | DMG для x64 и arm64 в `release/` |
| `pnpm build:win` | NSIS-установщик (запись пока не работает, см. выше) |

Все `build*` перед сборкой запускают `scripts/copy-ffmpeg.js`, который кладёт `ffmpeg`/`ffprobe` из `ffmpeg-ffprobe-static` в `bin/`.

### Стек

Electron 37 · Vue 3 + TypeScript · Vite 7 (`vite-plugin-electron`) · Pinia · Bootstrap 5 · fluent-ffmpeg + `ffmpeg-ffprobe-static` · electron-log · electron-builder.

### Архитектура

**Окна.** Четыре `BrowserWindow`, создаются при старте и дальше только показываются/скрываются. Все грузят один Vue-бандл с hash-роутингом:

| Окно | Маршрут | Назначение |
|---|---|---|
| Main | `/` | Настройки |
| Timer | `/timer` | Плавающий таймер и управление записью |
| SelectAria | `/select-aria` | Рамка выбора области |
| Border | `/border` | Зелёная рамка вокруг экрана во время записи (игнорирует мышь) |

**Состояние.** Источник истины — singleton `ScreenRecorder` в main-процессе. `setSettings()` сохраняет настройки в `dst-settings.json` и рассылает их всем окнам (`ExposedFfmpeg.UPDATED_SETTINGS`). Статус записи раз в секунду рассылается через `ExposedFfmpeg.UPDATED_STATE_TIMER`.

**Устройства.** `ffmpeg -f avfoundation -list_devices true` разбирается из stderr; экраны `Capture screen N` сопоставляются с `screen.getAllDisplays()` (основной дисплей всегда индекс 0), чтобы знать границы, `scaleFactor` и физическое разрешение.

**Запись.** Один вход `avfoundation` `"<video>:<audio>"`, `-capture_cursor 1`, видеофильтр `crop=…,scale=…`. Для области координаты рамки переводятся из логических в физические пиксели (Retina), обрезаются по границам экрана и округляются до чётных значений; масштаб вписывается в выбранный пресет с сохранением пропорций. Остановка — `q` в stdin FFmpeg (запасной вариант — `SIGINT`).

**Пауза.** `SIGSTOP`/`SIGCONT` процессу FFmpeg. AVFoundation при этом продолжает буферизовать кадры, и после продолжения они попадают в конец файла, поэтому при остановке, если были паузы, файл обрезается до реальной длительности: `ffmpeg -t <сек> -c copy` во временный файл с заменой оригинала.

**FFmpeg в собранном приложении.** Бинарник кладётся в `Contents/MacOS/ffmpeg` (`extraFiles`) и в `Resources/bin/` (`extraResources`). `initializeFfmpegPath()` проверяет кандидатов по порядку; `Contents/MacOS` предпочтительнее, чтобы macOS относила разрешение Screen Recording к самому приложению.

**Особенности упаковки.** `asar: false` и `node_modules` включаются целиком — из-за проблем с транзитивными зависимостями `fluent-ffmpeg`. Приложение скрывает Dock (`activationPolicy: accessory`) и не завершается при закрытии окон.

### CI и релизы

`.github/workflows/build-mac.yml` собирает DMG на каждый push/PR в `main` и выкладывает артефакты. На тег `v*` автоматически создаётся GitHub Release с DMG:

```bash
git tag v1.0.1 && git push origin v1.0.1
```

Не забудьте поднять `version` в `package.json`.

### Graphify

В `graphify-out/` лежит граф знаний по кодовой базе (используется Claude Code). После заметных изменений обновляйте его: `graphify update .`. Подробнее — [GRAPHIFY.md](GRAPHIFY.md).

## Решение проблем

| Симптом | Что проверить |
|---|---|
| Запись не стартует, диалог про доступ | Screen Recording / Microphone в Privacy & Security, затем перезапуск |
| В видео нет звука или только одна сторона | Устройство `Recorder-Input` выбрано, порядок «микрофон → BlackHole», системный выход направлен в BlackHole |
| Звук «плывёт» / рассинхрон | Источник тактов — физический микрофон, у BlackHole включена коррекция сноса |
| «FFmpeg binary not found» | В dev: `pnpm install`; при сборке: есть ли `bin/ffmpeg` (`node scripts/copy-ffmpeg.js`) |
| Нужные подробности | `~/Library/Logs/dst-recorder/main.log` — там полная команда FFmpeg и его stderr |

## Известные ограничения

- Только macOS.
- FPS (30), кодек и битрейт пока не настраиваются из UI.
- Раскладка аудиоканалов зашита в код и рассчитана на агрегатное устройство «микрофон + BlackHole».
- Интерфейс только на русском: файлы `src/locales/` есть, но vue-i18n в компонентах пока не используется.
- Приложение не подписано и не нотаризовано.
